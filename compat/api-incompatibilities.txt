# Semantic note: a data-format change, not a rename. The v0.0.3 alphabet had 33 symbols (present:
# L, absent: U, contradicting its own doc comment); the new one is 32-symbol Crockford base32
# (I/L/O/U excluded). v0.0.3-encoded values no longer decode under this package: strings containing
# L fail with "invalid character", and every other multi-character string decodes to different bytes
# (M-Z shift one position, and the base changed 33->32). Persisted IDs, codes and cache keys must
# be re-encoded or migrated with the old alphabet kept as a table. See "Base32 identifiers changed
# alphabet" in compat/behavior-changes.md.
